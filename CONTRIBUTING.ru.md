## Первые шаги и настройка рабочего места

### 1. Предварительные требования
- **Node.js**: Версия 18.x или выше (протестировано на Node.js v20 LTS и v24).
- **npm**: Версия 9.x или выше.
- **Git**: Для контроля версий.
- *(Опционально)* **Google Antigravity SDK & CLI**: Для живого тестирования с `agy.exe`.

### 2. Клонирование и установка
```bash
# 1. Клонируйте форк репозитория
git clone https://github.com/<ваш-логин>/antigravity-apex.git
cd antigravity-apex

# 2. Установите зависимости бэкенда и фронтенда
npm install
npm --prefix client install

# 3. Создайте локальную конфигурацию окружения
cp .env.example .env

# 4. Запустите полный набор тестов верификации
npm test
```

### 3. Запуск в режиме разработки
```bash
# Запуск бэкенда (порт 3001) и фронтенда Vite (порт 5173) в параллельном режиме
npm run dev
```
Откройте браузер по адресу:
- Фронтенд: `http://127.0.0.1:5173`
- Бэкенд статус: `http://127.0.0.1:3001/api/status`

## Стандарты инженерии и разработки

### 1. Строгий TypeScript без `any`
- Весь код бэкенда и фронтенда обязан быть строго типизирован.
- Запрещено использовать тип `any` в качестве обходного пути. Все структуры данных должны описываться интерфейсами.
- Входные данные API обязательно валидируются через схемы **Zod**.

### 2. Дизайн-система Refero / Vercel
- Интерфейс оформлен в стилистике **Refero / Vercel** с поддержкой Светлой и Тёмной тем.
- Сетка 4px/8px, использование токенов из `client/src/index.css`.
- Обязательное наличие видимого кольца фокуса (`focus-ring`), контрастности по WCAG 2.1 AA и всех состояний элементов (hover, active, disabled).

### 3. Регламент 9-пунктного отчёта субагентов
Любые изменения логики выполнения задач или работы субагентов обязаны поддерживать **9-пунктный отчёт**:
1. `taskName` (Название задачи)
2. `status` (`SUCCESS`, `FAILURE`, `BLOCKED`)
3. `summary` (Резюме сделанного)
4. `modifiedFiles` (Изменённые файлы)
5. `executedChecks` (Выполненные проверки)
6. `checkResults` (Результаты проверок)
7. `issuesAndRisks` (Риски и проблемы)
8. `pendingItems` (Незавершённое)
9. `nextSteps` (Дальнейшие шаги)

Запрещено утверждать «все тесты пройдены» без приведения реального вывода тестового раннера.

## Отправка Pull Request

1. Создайте отдельную ветку от `main`:
   ```bash
   git checkout -b feat/your-feature-name
   ```
2. Внесите изменения с соблюдением стандартов проекта.
3. Запустите тесты и диагностику:
   ```bash
   npm test
   npm run doctor
   ```
4. Оформите коммиты по стандарту [Conventional Commits](https://www.conventionalcommits.org/ru/):
   ```bash
   git commit -m "feat(telemetry): add streaming token throughput counter"
   ```
5. Отправьте ветку в свой форк и откройте Pull Request в ветку `main`.
