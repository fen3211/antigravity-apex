## Сообщение об уязвимости

Мы крайне серьёзно относимся к безопасности AI Command Center и подключённых окружений Google Antigravity. Если вы обнаружили потенциальную уязвимость или брешь в защите, пожалуйста, следуйте процедуре ответственного раскрытия:

1. **НЕ публикуйте публичные Issue или обсуждения на GitHub** с описанием уязвимостей.
2. Отправьте отчёт приватно через **GitHub Private Security Advisories** или по электронной почте:
   `security@ai-command-center.local` (либо свяжитесь с мейнтейнерами через контакты профиля GitHub).
3. **Информация, которую необходимо включить в отчёт**:
   - Подробное описание уязвимости и вектора атаки.
   - Воспроизводимый пример (Proof of Concept, PoC) или пошаговые инструкции.
   - Затронутый компонент (роутер API, WebSocket-сервер, CLI-мост, супервизор процессов, база данных SQLite).
   - Потенциальный ущерб (выполнение произвольного кода RCE, повышение привилегий, обход путей Path Traversal, отказ в обслуживании DoS).
   - Предлагаемый патч или исправление, если они подготовлены.

### Сроки рассмотрения
- **Первичное подтверждение получения**: в течение 24–48 часов.
- **Триаж и оценка критичности**: в течение 72 часов.
- **Выпуск патча и публикация бюллетеня**: обычно в течение 7–14 дней в зависимости от критичности.

## Архитектура безопасности и встроенные механизмы защиты

AI Command Center реализует эшелонированную защиту, адаптированную для локальных дашбордов ИИ-оркестрации:

### 1. Привязка к Loopback и белый список CORS
- По умолчанию сервер слушает строго локальный интерфейс замыкания (`127.0.0.1`).
- Серверы Express HTTP и WebSocket валидируют входящие запросы по строгому белому списку источников (`CONFIG.ALLOWED_ORIGINS`). Сторонние сайты в браузере не могут отправлять междоменные запросы для выполнения команд или чтения телеметрии.

### 2. Криптографический токен API и timing-safe проверка
- Системные операции требуют аутентификации через 32-байтный криптографический hex-токен (`COMMAND_CENTER_API_KEY`).
- Проверка токена использует `crypto.timingSafeEqual` для полного исключения атак по времени (Timing Attacks).
- Эндпоинт начального получения токена (`GET /api/auth/token`) доступен только с адресов локального замыкания (loopback) и разрешённых браузерных источников.

### 3. Защита от инъекций команд и изоляция подпроцессов
- Выполнение произвольных терминальных команд категорически запрещено.
- Взаимодействие с Antigravity ограничено строгим белым списком аргументов (`agy models`, `agy agents`, `agy plugins list`, `agy -p`).
- Спецсимволы шелла (`&`, `|`, `;`, `$`, `>`, `<`, `` ` ``) отклоняются на уровне роутера с кодом 400.
- В Windows процессы субагентов завершаются через принудительное уничтожение дерева процессов (`taskkill /T /F`), что исключает появление процессов-зомби.

### 4. Защита от обхода путей (Path Traversal)
- Чтение и запись в базу знаний Директора (`~/.gemini/antigravity/knowledge/ai-director/`) строго ограничены `.md` файлами без последовательностей обхода (`..`, `/`, `\`).
- Парсер транскриптов считывает только проверенные файлы по строгому предикату путей.

### 5. Очистка промпт-паков эскалации к Gemini 4 Argon
- Системные пути, содержащие имя пользователя ОС (`C:\Users\<username>` $\to$ `~`), автоматически маскируются регулярными выражениями перед формированием промпт-пака.
- Секреты окружения, API-ключи и учетные данные заменяются на безопасные плейсхолдеры.

### 6. Запрет несанкционированного деплоя
- Агентам и скриптам категорически запрещено выполнять несанкционированные production-релизы.
