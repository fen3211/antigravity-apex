# Руководство по устранению неполадок и диагностике

[English](TROUBLESHOOTING.md) • [Русский](TROUBLESHOOTING.ru.md)

В этом руководстве собраны диагностические шаги и практические решения для типичных проблем, возникающих при работе с **AI Command Center**.

---

## 1. Отключение WebSocket и статус «DISCONNECTED»

### Симптомы
- Индикатор статуса в шапке дашборда показывает **DISCONNECTED** или **RECONNECTING**.
- Поток событий в разделе «Events» перестаёт обновляться в реальном времени.

### Диагностика
1. Откройте панель разработчика браузера (F12) и перейдите на вкладку **Network** $\to$ фильтр **WS**.
2. Обратите внимание на код закрытия WebSocket-соединения:
   - `1008 (Policy Violation)`: Ошибка авторизации (недействительный API-ключ) или неразрешённый Origin.
   - `1009 (Message too large)`: Размер единичного сообщения превысил лимит 64 КБ.
   - `1006 (Abnormal Closure)`: Процесс сервера упал или прервано сетевое соединение.

### Решение
- **Несовпадение токена**: Откройте в браузере `http://127.0.0.1:3001/api/auth/token`. Клиент автоматически получит и сохранит актуальный токен.
- **Несовпадение Origin**: Если вы открываете дашборд по внешнему адресу (например, `http://192.168.1.50:5173`), добавьте этот адрес в массив `CONFIG.ALLOWED_ORIGINS` в `server/src/config.ts`.
- **Перезапуск сервера**: Если бэкенд завершился с ошибкой, проверьте вывод терминала и перезапустите сервер через `npm run dev` или `start.cmd`.

## 2. Не видны сессии Antigravity или файлы транскриптов

### Симптомы
- В разделе **Mission Control** отображается `0 активных блокировок` и `0 живых транскриптов`, хотя Antigravity запущен в соседнем терминале.

### Диагностика
1. Проверьте базовые пути Antigravity в логах запуска бэкенда:
   ```text
   [AI COMMAND CENTER] Antigravity dir: C:\Users\<user>\.gemini\antigravity
   [AI COMMAND CENTER] Knowledge dir:   C:\Users\<user>\.gemini\antigravity\knowledge\ai-director
   ```
2. Убедитесь, что файлы присутствуют на диске:
   - Блокировки присутствия: `~/.gemini/antigravity/presence/`
   - Транскрипты: `~/.gemini/antigravity/brain/**/.system_generated/logs/transcript.jsonl`

### Решение
- **Переопределение путей в `.env`**: Если Antigravity установлен в нестандартном месте, укажите пути явно:
  ```env
  ANTIGRAVITY_DIR=D:\CustomPath\.gemini\antigravity
  BRAIN_DIR=D:\CustomPath\.gemini\antigravity\brain
  PRESENCE_DIR=D:\CustomPath\.gemini\antigravity\presence
  KNOWLEDGE_DIR=D:\CustomPath\.gemini\antigravity\knowledge\ai-director
  ```
- **Права доступа**: Убедитесь, что у процесса Node.js есть права на чтение каталога `.gemini`.

## 3. Зависание субагента или превышение таймаута

### Симптомы
- Задача бесконечно остаётся в статусе `in_progress`.
- В терминале процесс запущенного субагента перестал выводить логи.

### Диагностика
1. Перейдите в раздел **Task Manager**.
2. Выберите зависшую задачу и посмотрите её PID и статус супервизора.

### Решение
- **Отмена из интерфейса**: Нажмите кнопку **Отменить задачу** (Cancel Task) в карточке задачи. Супервизор немедленно отправит сигнал завершения.
- **Принудительное завершение дерева процессов**: Если процесс завис наглухо, супервизор вызовет принудительное завершение всего дерева процессов. В Windows при необходимости можно завершить вручную из PowerShell:
  ```powershell
  taskkill /PID <PID> /T /F
  ```
- **Увеличение таймаута**: Для длительных сборок или E2E-тестов увеличьте параметр `timeoutMs` при вызове `/tasks/:id/execute`:
  ```json
  {
    "timeoutMs": 300000
  }
  ```

## 4. Блокировка базы SQLite (`SQLITE_BUSY: database is locked`)

### Симптомы
- Запросы к REST API возвращают HTTP 500 с сообщением `SQLITE_BUSY: database is locked`.

### Диагностика
1. Проверьте, не открыт ли файл `command_center.sqlite` во внешней утилите (например, DB Browser for SQLite) с монопольной блокировкой.
2. Проверьте наличие WAL-файлов: `command_center.sqlite-wal` и `command_center.sqlite-shm`.

### Решение
- **Закройте внешние просмотрщики**: Закройте сторонние GUI-клиенты, удерживающие монопольный доступ.
- **Прагма WAL**: AI Command Center по умолчанию использует режим WAL и `busy_timeout = 5000` мс.
- **Сброс базы**: При фатальном повреждении удалите файлы `command_center.sqlite*`. Сервер автоматически создаст свежие таблицы при следующем старте.

## 5. Правовой шлюз возвращает `BLOCKED_RED`

### Симптомы
- Задача не проходит Quality Gate 2b со статусом `BLOCKED_RED`.

### Диагностика
1. Изучите сформированное заключение `LegalAssessment` в карточке задачи или сделайте запрос к `GET /api/events?type=legal_gate.blocked`.
2. Проанализируйте поля `identifiedRisks` и `mechanismOfNonCompliance`.

### Типичные причины и исправления
- **Вирусная лицензия (AGPL/GPL)**: В закрытую или облачную кодовую базу попала библиотека под AGPL-3.0 или GPL-3.0. Замените её аналогом под MIT, Apache-2.0 или BSD.
- **Локализация ПДн в РФ (23-ФЗ)**: База данных с персональными данными граждан РФ создана за рубежом без первичной записи в РФ. Обеспечьте первичную запись на сервере в РФ перед репликацией.
- **Предустановленный чекбокс (69-ФЗ)**: Форма согласия или оплаты содержит заранее проставленную галочку. Снимите предвыбор (запрет темных паттернов с 01.09.2025).
- **Помните о неблокирующем инварианте**: При статусе `BLOCKED_RED` блокируется только конкретная рискованная подзадача. Разработка дизайна, верстки и юнит-тестов продолжается без остановок.

## 6. Отклонение выполнения CLI (`Agent not allowed` / `Command failed`)

### Симптомы
- Запуск задачи через Control Center возвращает ошибку `error: Agent "<name>" is not allowed` или `Invalid CLI arguments`.

### Диагностика
1. Проверьте белый список разрешённых агентов: `GET /api/control/settings`.
2. Проверьте промпт на наличие запрещённых спецсимволов шелла: `&`, `|`, `;`, `$`, `>`, `<`, `` ` ``.

### Решение
- Убедитесь, что ID агента присутствует в `settings.allowedAgents`. Добавить новые роли можно в настройках Control Center.
- Уберите цепочки операторов шелла из промпта. Передавайте в `agy.exe` только чистый текст инструкций.
