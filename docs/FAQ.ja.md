# よくある質問と回答 (FAQ)

本文書は、**Antigravity Apex** に関する技術的、構造的、運用上の疑問について包括的にお答えします。

---

## 1. 概要とシステム構成

### Antigravity Apex とは何ですか？
Antigravity Apex は、**Google Antigravity** マルチエージェント環境および **AI Development Director** 運用フレームワークのためのローカル専用ミッションコントロールダッシュボードです。稼働中の自律型サブエージェント、アクティブセッション、トークン消費量、および品質ゲートの状況を一目で把握できる統合的な可観測性を提供します。

### Antigravity Apex は Antigravity CLI や IDE を置き換えるものですか？
いいえ。Antigravity Apex は Antigravity の上位に位置する運用監視レイヤーとして機能します。Antigravity が実際のコード編集やツール呼び出しを実行し、Antigravity Apex がその実行トランスクリプトを監視し、並行数を制御し、品質ゲートを判定し、困難なデッドロック発生時に Level 4 Argon へのエスカレーションを統制します。

### Antigravity がインストールされていないマシンでも動作しますか？
はい。完全に疎結合で設計されているため、Antigravity がローカルで動作していない場合でも、ダッシュボードはオフラインタスク管理、Director ナレッジ編集、およびシミュレートされたテレメトリを用いて問題なく稼働します。

### どの OS に対応していますか？
Antigravity Apex は以下で動作検証されています：
- **Windows 10 / 11** (64ビット)
- **macOS 12+** (Apple Silicon および Intel)
- **Linux** (Ubuntu 22.04+、Debian 11+、Fedora、Arch Linux)

## 2. 並行処理とパフォーマンス

### 何個のサブエージェントを並行して動かせますか？
システムは最大 **6つの並行サブエージェント** (`MAX_CONCURRENT_SUBAGENTS = 6`) をサポートしています。デフォルトでは、システムの応答性を維持し API のレート制限を避けるため、**3並行** にスロットリングされています。また、高コストな Pro モデルの同時実行は最大 **2インスタンス** までに制限されています。

### 「ゼロディスクリード」ログ取り込みとは何ですか？
一般的なログ監視ツールは、ファイルに少しでも変更があると、先頭からファイル全体を再パースします。長時間のセッションでログが数十メガバイトに達すると、深刻な CPU およびディスク I/O のスパイクを招きます。

Antigravity Apex の `JsonlStreamReader` は、SQLite 内でファイルごとの正確なバイトオフセット（`last_offset`）を記憶します。ファイル更新時には、その位置から新しく追記された 64 KB のチャンクのみをピンポイントで読み取ります。UTF-8 の境界保護機構も備えており、無駄なディスク I/O を完全に排除します。

### ダッシュボードの実行が開発環境のビルドを重くしませんか？
影響はごくわずかです。バックエンドは軽量な Node.js イベントループ上で動作し、C++ ネイティブの `better-sqlite3`（WAL モード）を採用しているため、アイドル時の CPU 使用率は 1% 未満、メモリフットプリントは約 60 MB に収まります。

## 3. モデル選択とトークン消費

### どの AI モデルが使用されますか？
Google Gemini ファミリーを用途に応じて使い分けます：
- **Gemini 3.8 Flash High**: Director の統括判断、タスク判定、品質裁定。
- **Gemini Flash (Medium/Low)**: 高速かつ低コストな標準開発（フロントエンド、バックエンド、QA、レビュー、調査などの日常タスク）。
- **Gemini Pro**: 深層アーキテクチャ設計、並行競合解析（Level 3 Senior Architect）。
- **Gemini 4 Argon**: 致命的な行き詰まりに対する閉ループ環境での最高峰推論（Level 4）。

### LIVE と ESTIMATED のトークン指標の違いは何ですか？
- **LIVE**: Antigravity の実際の実行ログ（`transcript.jsonl`）から抽出された確定値。エージェントが実際に消費した入力・出力・キャッシュ読み取りトークンを正確に反映します。
- **ESTIMATED**: リアルタイムセッション外で手動作成されたタスクに対し、過去の平均値から算出した予測値。

### なぜ Gemini 4 Argon は「閉ループ (Closed Contour)」で運用するのですか？
Gemini 4 Argon は、重大な構造的行き詰まりを打破するための超強力な推論モデルです。トークンの過剰消費や不用意なコード改変を防ぐため：
1. 軽微なエラーでは決して発動しません（異なるアプローチで 2 回連続失敗した後にのみ移行）。
2. 機密情報をマスクし、20〜50 行の最小限の再現コードに絞り込んだ **18項目プロンプトパック** のみを受け取ります。
3. 人間オペレーターが手動で Argon に切り替えて実行します。
4. Argon は直接コードをコミットするのではなく、診断結果と解決戦略を提示し、実際のコード実装は Flash 専門家へと戻されます。

## 4. 品質ゲートと法令ガバナンス

### サブエージェントレポートの「必須 9項目」とは何ですか？
技術エージェントがタスクを完了して Gate 1 を通過するためには、以下の 9 項目を網羅したレポートを提出しなければなりません：
1. `taskName`（タスク名）
2. `status`（成否: `SUCCESS`, `FAILURE`, `BLOCKED`）
3. `summary`（作業概要）
4. `modifiedFiles`（変更ファイル一覧）
5. `executedChecks`（実行した検証コマンド）
6. `checkResults`（検証結果のログ出力）
7. `issuesAndRisks`（既知のリスク）
8. `pendingItems`（残課題）
9. `nextSteps`（推奨する次の手順）

テストランナーの客観的出力なしに「全テスト合格」とだけ記載された報告は自動的に却下されます。

### 品質ゲート 2b（法令ゲート）とは何ですか？
コード実装やリリースの前に、ロシア連邦（`RU`）および欧州連合（`EU_NL`）の法令に抵触しないかを自動監査する仕組みです：
- ロシア法令: 152-FZ（個人データ）、156-FZ（個別同意）、23-FZ（国内DB初回記録義務）、149-FZ（情報法・ORI 登録）、243-FZ（AI 規制）、民法第4部（著作権）、38-FZ/479-FZ（広告・3%拠出金）、69-FZ（ダークパターン禁止）、54-FZ（オンラインレジ）。
- 欧州規制: GDPR（規則 2016/679）、EU AI Act（規則 2024/1689）、ePrivacy 指令。

### 法令ゲートは人間の弁護士を代替できますか？
いいえ。Gate 2b は開発の初期段階で明白な法令違反を検知するための技術的スキャナーです。深刻なリスク（`RED` 判定や複雑な越境データ移転）がある場合は、有資格の法務専門家（弁護士）への相談が必須として勧告されます。

### `RED` 判定時の「非ブロッキング分離」とは何ですか？
法令ゲートが `BLOCKED_RED` を検出した場合、**違法リスクのある特定のサブタスクのみが停止** されます。無害な UI のスタイリング、デザイン設計、単体テスト作成といった並行作業は停止することなくそのまま継続できます。

## 5. カスタマイズと拡張

### 17の専門ロールプールに新しいエージェントを追加できますか？
はい、簡単に追加できます：
1. `~/.gemini/config/plugins/ai-director/agents/<role-id>.md` に Markdown 形式でエージェント定義を作成します。
2. ダッシュボードの **Control Center** 設定画面または `POST /api/control/settings` を通じて、その ID を `allowedAgents` に追加します。
3. エージェント管理グリッドに即座に反映され、タスクを割り当てられるようになります。

### リモートサーバーで Antigravity Apex を運用するには？
`.env` で `HOST=0.0.0.0` を設定し、`CONFIG.ALLOWED_ORIGINS` に許可するアクセス元ドメインを追加します。リクエストヘッダーに `Authorization: Bearer <API_KEY>` を付与することで、セキュアにリモート管理できます。
