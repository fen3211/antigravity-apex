# Справочник конфигурации (Configuration Reference)

В данном документе представлен подробный справочник всех статических параметров и динамических настроек времени выполнения **Antigravity Apex**.

---

## 1. Переменные окружения (`.env`)

Antigravity Apex считывает конфигурационные параметры из файла `.env` с помощью библиотеки `dotenv`. Все параметры снабжены безопасными значениями по умолчанию, готовыми к промышленной эксплуатации.

### Сеть и среда выполнения сервера

| Переменная | Тип данных | Значение по умолчанию | Описание |
|------------|------------|-----------------------|----------|
| `PORT` | `number` | `3001` | Сетевой порт HTTP и WebSocket, на котором запускается Express-сервер бэкенда. |
| `HOST` | `string` | `127.0.0.1` | Сетевой адрес интерфейса для привязки сокета. По умолчанию привязан к локальному интерфейсу (loopback) для обеспечения локальной безопасности. |
| `NODE_ENV` | `string` | `development` | Режим среды выполнения Node.js. Установите в `production` для включения оптимизированного кэширования и отключения избыточного логирования. |

### Безопасность и аутентификация

| Переменная | Тип данных | Значение по умолчанию | Описание |
|------------|------------|-----------------------|----------|
| `COMMAND_CENTER_API_KEY` | `string` | *(Генерируется автоматически)* | 32-байтный криптографический hex-токен (64 шестнадцатеричных символа), обязательный для вызова всех изменяющих состояние REST-эндпоинтов и для рукопожатия WebSocket. Если переменная пуста, сервер автоматически генерирует ключ при первом старте и сохраняет его в файл `.env`. |

### Пути к файловой системе Google Antigravity

По умолчанию пути вычисляются относительно домашнего каталога пользователя (`~/.gemini/antigravity`). Вы можете переопределить любой из них индивидуально:

| Переменная | По умолчанию (Windows) | По умолчанию (Linux/macOS) | Описание |
|------------|------------------------|----------------------------|----------|
| `ANTIGRAVITY_DIR` | `%USERPROFILE%\.gemini\antigravity` | `~/.gemini/antigravity` | Базовый каталог установки среды Google Antigravity. |
| `KNOWLEDGE_DIR` | `%USERPROFILE%\.gemini\antigravity\knowledge\ai-director` | `~/.gemini/antigravity/knowledge/ai-director` | Каталог с регламентами и протоколами AI Development Director в формате Markdown. |
| `PRESENCE_DIR` | `%USERPROFILE%\.gemini\antigravity\presence` | `~/.gemini/antigravity/presence` | Каталог, отслеживаемый на предмет появления `.lock`-файлов активных сессий. |
| `BRAIN_DIR` | `%USERPROFILE%\.gemini\antigravity\brain` | `~/.gemini/antigravity/brain` | Каталог, содержащий транскрипты выполнения субагентов (`transcript.jsonl`). |
| `AGY_CLI_PATH` | `%LOCALAPPDATA%\agy\bin\agy.exe` | `/usr/local/bin/agy` | Путь к исполняемому файлу CLI Antigravity. |
| `DB_PATH` | `./command_center.sqlite` | `./command_center.sqlite` | Путь к локальному файлу базы данных SQLite. |

## 2. Динамические настройки управления (Runtime API)

Помимо статических переменных `.env`, Antigravity Apex хранит операционные параметры рантайма в таблице `settings` базы данных SQLite. Их можно изменять на лету через веб-интерфейс (**Центр управления / Control Center**) либо через REST API:

- **Эндпоинты**: `GET /api/control/settings` и `POST /api/control/settings`
- **Аутентификация**: Требуется заголовок `Authorization: Bearer <API_KEY>`, `x-api-key: <API_KEY>` или query-токен `?token=<API_KEY>`.

### Схема параметров (JSON)

```json
{
  "maxConcurrentAgents": 3,
  "maxRetryAttempts": 2,
  "defaultModelTier": "gemini-3.8-flash-high",
  "escalationPolicy": "strict",
  "autoQualityGates": true,
  "allowedAgents": [
    "director",
    "researcher",
    "frontend-developer",
    "backend-developer",
    "ui-ux-designer",
    "qa-engineer",
    "code-reviewer",
    "senior-architect",
    "legal-compliance",
    "security-engineer",
    "devops-engineer",
    "product-manager",
    "ai-evaluation-engineer",
    "performance-engineer",
    "accessibility-specialist",
    "database-specialist",
    "data-engineer"
  ]
}
```

### Подробное описание параметров

1. `maxConcurrentAgents` (целое число, диапазон 1–10):
   Определяет максимальное количество процессов субагентов, которые супервизор может запускать одновременно. Рекомендуемое значение: `3` для стандартной разработки; максимальное протестированное значение: `6`.
2. `maxRetryAttempts` (целое число, диапазон 1–10):
   Максимальное число повторных попыток на один подход до срабатывания автоматической эскалации Уровня 3 к Senior Architect. По умолчанию: `2`.
3. `defaultModelTier` (строка):
   Базовый уровень модели Gemini, назначаемый новым задачам. Стандартное значение: `gemini-3.8-flash-high`.
4. `escalationPolicy` (`"strict"` | `"relaxed"`):
   - `"strict"`: Немедленно блокирует задачу при двух последовательных неудачах одного подхода и запускает синтезатор пакета эскалации к Gemini 4 Argon.
   - `"relaxed"`: Разрешает одну дополнительную попытку перед эскалацией.
5. `autoQualityGates` (булево значение):
   При значении `true` система автоматически запускает проверки Шлюза качества 1 (Quality Gate 1: линтер, сборка, типы) при отправке 9-пунктного отчёта субагентом.
6. `allowedAgents` (массив строк):
   Строгий белый список идентификаторов агентов, которым разрешён запуск через мост супервизора. Предотвращает запуск неавторизованных или фиктивных ролей.

## 3. Политика CORS и белый список источников

Бэкенд строго контролирует происхождение входящих кросс-доменных запросов через массив `CONFIG.ALLOWED_ORIGINS`:

```typescript
ALLOWED_ORIGINS: [
  'http://localhost:5173',
  'http://127.0.0.1:5173',
  'http://localhost:3000',
  'http://127.0.0.1:3000',
  'http://localhost:3001',
  'http://127.0.0.1:3001'
]
```

Запросы с неавторизованных источников немедленно отклоняются промежуточным обработчиком с кодом **HTTP 403 Forbidden** (`Blocked by CORS policy: Origin not allowed`). При запуске фронтенда на нестандартном порту или доменном имени добавьте соответствующий адрес в `CONFIG.ALLOWED_ORIGINS` в файле `server/src/config.ts`.

## 4. Эксплуатационные параметры WebSocket

Сервер WebSocket (`ws://127.0.0.1:3001/ws`) функционирует в строгих рамках отказоустойчивости и защиты от перегрузок:

- **Максимальный размер полезной нагрузки (Max Payload Size)**: `64 КБ` (`MAX_WS_PAYLOAD = 64 * 1024`). Любой входящий фрейм, превышающий данный лимит, отклоняется с закрытием сокета по коду `1009 (Message too large)` и немедленным разрывом сетевого соединения (`terminate()`).
- **Интервал Heartbeat (Keep-Alive)**: 30 секунд. Сервер отправляет контрольные пакеты `ping`, на которые клиент обязан ответить `pong`. Зависшие или отключившиеся сокеты автоматически удаляются из пула рассылки.
- **Аутентификация соединения**: Требует валидного API-ключа, переданного одним из следующих способов:
  - Query-параметр URL: `?token=<API_KEY>`
  - Заголовок: `Authorization: Bearer <API_KEY>`
  - Заголовок: `x-api-key: <API_KEY>`
- **Защита от атак по времени**: Проверка токена осуществляется с использованием криптографически безопасного побайтового сравнения постоянного времени `crypto.timingSafeEqual()`.

## 5. Фильтрация файлового наблюдателя Chokidar

Файловый наблюдатель Chokidar инспектирует изменения файловой системы исключительно через фильтр `createAntigravityPathFilter(brainDir, presenceDir)`:

### Разрешённые файлы:
- Любые файлы с расширением `.lock` внутри каталога `PRESENCE_DIR`.
- Любые файлы с именем `transcript.jsonl`, расположенные внутри подкаталогов `.system_generated/logs/` в каталоге `BRAIN_DIR`.

### Исключаемые и игнорируемые объекты:
- Временные файлы редакторов и загрузок: `.tmp`, `.swp`, `~*`, `.bak`, `~$*`, `.crdownload`.
- Точечные (скрытые) файлы и служебные каталоги (за исключением каталога `.system_generated`).
- Тяжёлые каталоги сборки, зависимостей и временных данных: `node_modules`, `.git`, `dist`, `scratch`, `tempmediaStorage`, `.user_uploaded`.
